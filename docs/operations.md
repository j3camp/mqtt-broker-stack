# Operations

## Quick Start

```bash
# 1. Initialise (creates .env, certificates, and admin user)
./scripts/init.sh

# 2. Start the broker
make up

# 3. Check status
make status

# 4. View logs
make logs
```

## Initialization

```bash
# Interactive
./scripts/init.sh

# Non-interactive
MQTT_INITIAL_USERNAME=admin \
MQTT_INITIAL_PASSWORD='change-me' \
MQTT_SERVER_HOSTNAME=mqtt.example.local \
./scripts/init.sh
```

Use `--force` to regenerate secrets.

## User Management

```bash
# Create user
./scripts/create-user.sh <username>

# Change password
./scripts/change-password.sh <username>

# Delete user
./scripts/delete-user.sh <username>
```

Passwords are never passed as command-line arguments. You will be prompted interactively,
or set `MQTT_NEW_PASSWORD` environment variable for non-interactive use.

Note: Mosquitto does not support live reload of the password file. The scripts will restart
the broker after modifications.

## Certificate Management

Development certificates are generated by `scripts/generate-cert.sh`:

```bash
./scripts/generate-cert.sh --hostname mqtt.example.local --ip 192.168.1.10
```

The CA private key is stored in `certs/ca/` and is **never** committed to Git.

For production, replace the generated certificates with certificates from a trusted CA.
Update the paths in `mosquitto/config/conf.d/30-external.conf` if needed.

## ACL Management

```bash
# Enable ACL (requires mosquitto/config/security/acl to exist)
./scripts/enable-acl.sh

# Disable ACL
./scripts/disable-acl.sh
```

## Backup and Restore

```bash
# Create backup
./scripts/backup.sh

# Restore from backup
./scripts/restore.sh backups/mqtt-broker-backup-<timestamp>.tar.gz
```

Backups include: configuration, public certificates, password file, runtime ACL, and persistence data.
Backups do NOT include: CA private key, server private key.

## Validation

```bash
# Full validation
./scripts/validate.sh

# Quick validation (no Docker required)
./scripts/validate.sh --quick
```

## Integration Tests


## Makefile Targets

| Target | Description |
|--------|-------------|
| `make init` | Initialize the stack |
| `make up` | Start the broker |
| `make down` | Stop containers |
| `make restart` | Restart the broker |
| `make status` | Show service status |
| `make logs` | Follow broker logs |
| `make validate` | Validate configuration |
| `make test` | Run integration tests |
| `make create-user USERNAME=<name>` | Create MQTT user |
| `make change-password USERNAME=<name>` | Change user password |
| `make delete-user USERNAME=<name>` | Delete MQTT user |
| `make enable-acl` | Enable ACL |
| `make disable-acl` | Disable ACL |
| `make backup` | Create backup |
| `make restore ARCHIVE=<path>` | Restore from backup |
| `make clean FORCE=1` | Remove all runtime data |

## Troubleshooting

### Broker fails to start

```bash
# Check logs
docker compose logs mosquitto

# Validate configuration
./scripts/validate.sh
```

### TLS connection errors

- Verify the certificate SAN matches the hostname you are connecting to.
- Verify clients use the correct CA certificate (`mosquitto/config/certs/ca.crt`).
- Check certificate expiry: `openssl x509 -noout -dates -in mosquitto/config/certs/server.crt`

### Authentication failures

- Verify the user exists in the password file.
- Verify the password file has correct permissions (600).
- Ensure `allow_anonymous false` is set in `30-external.conf`.

## Production Deployment Checklist

- [ ] Use a trusted CA certificate (not self-signed).
- [ ] Set strong passwords for all MQTT users.
- [ ] Configure `MQTT_TLS_BIND_ADDRESS` appropriately (restrict if possible).
- [ ] Verify port 1883 is not exposed beyond the Docker host.
- [ ] Review and configure ACL if needed.
- [ ] Set up automated backups.
- [ ] Monitor broker logs.
- [ ] Test certificate rotation procedure.
- [ ] Keep Mosquitto image version pinned and up-to-date.
- [ ] Document your network trust boundaries.
